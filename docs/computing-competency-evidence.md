# Research-Computing Competency Evidence

This page points to concrete repository evidence rather than listing software names without examples.

| Competency | Repository evidence |
|---|---|
| Problem decomposition and pseudocode | `docs/reproducible-workflow.md` defines the computational problem, pipeline, invariants, and failure conditions. |
| Source preservation | `data/raw_public/` contains a sanitized, immutable source-layout reconstruction; derived files are regenerated by scripts. |
| Messy tabular data | `analysis/python/step01_clean_harvest.py` handles blank group labels, irregular source headers, numeric validation, and compact identifiers without manual spreadsheet edits. |
| Excel ingestion in R | `analysis/r/step01_clean_harvest_excel.R` selects the `Harvest` sheet, removes the report header row, forward-fills grouped labels, parses codes, and verifies parity with the canonical CSV. |
| Regular expressions | `analysis/python/plot_codes.py` and the R cleaning script strictly parse `L1IR2F3R1`-style identifiers. |
| R / tidyverse | `analysis/r/step02_tidyverse_analysis.R` uses `select`, `mutate`, `if_else`, `filter`, `group_by`, `summarise`, and `ggplot2` on the field data. |
| Joins and reshaping | `analysis/python/step02_reshape_join.py` and `analysis/r/step03_reshape_join.R` create long-form outcomes and join treatment metadata; the R script also demonstrates `pivot_wider`. |
| Python / Pandas | `analysis/notebooks/reproducible_yield_walkthrough.ipynb` uses DataFrames, `.loc`, `.iloc`, `assign`, `np.where`, `dropna`, `groupby`, `agg`, pivoting, functions, conditions, and plotting. |
| Descriptive statistics | `analysis/python/step03_descriptive_yield.py` produces marginal and factorial-cell summaries. |
| Experimental-design judgement | `docs/statistical-identification.md` distinguishes rows from assignment units and explains why a naive plot-level error term may be invalid. |
| Transparent exploratory inference | `analysis/python/step05_exploratory_factorial.py` exposes the balanced ANOVA mechanically while labeling it non-confirmatory. |
| Visualization | `analysis/python/step06_figures.py`, the R workflow, and `figures/` generate analysis-linked plots rather than manually edited screenshots. |
| Automated checking | `tests/` checks unique plots, factorial completeness, code parsing, source rebuild parity, benchmark means, and preservation of flagged values. |
| Reproducible execution | `Makefile`, `analysis/python/reproduce_all.py`, and `.github/workflows/reproduce.yml` provide one-command local and CI execution. |
| Data governance | `DATA_USE.md`, `docs/data-management.md`, `docs/source-provenance.md`, and the metadata registers separate public reproducibility inputs from restricted originals. |
| Multi-language portability | Python is the tested reference path; R and Stata restate the analytical logic without changing the evidentiary claims. |

## Skills not claimed from this repository

The repository does not claim competence merely because a method appears on a CV. In particular, it does not force difference-in-differences, instrumental variables, regression discontinuity, or a complex panel model onto a dataset that does not support those designs.

Likewise, a GitHub ZIP cannot demonstrate day-to-day version-control behaviour. Meaningful commit history, pull/push discipline, and collaboration practices must be demonstrated through how the repository is maintained after publication.
